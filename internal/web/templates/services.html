Convierte una aplicación (por ejemplo, el catálogo de libros o un script) en un servicio de systemd: transfiere sus archivos a la VM por SSH, le crea un usuario propio con los permisos justos y registra la unidad. Abajo se gestiona cualquier unidad con start, stop, restart, status, enable y disable.

1. Desplegar una aplicación como servicio en {{.Cur.Label}}

Se crea /etc/systemd/system/<nombre>.service, la carpeta /opt/<nombre> y el usuario svc-<nombre>. Una carpeta con el ejecutable y lo que necesita (plantillas, estáticos, base de datos…) o un solo archivo. Se transfiere todo menos .git y .DS_Store. Ruta relativa a la carpeta. Si indicó un solo archivo, déjelo vacío. Debe ser un binario de Linux (no de macOS) o un script con #!.

2. Gestionar una unidad

Si no indica sufijo se usa .service. No se permite detener ni deshabilitar ssh, la red ni servicios básicos del sistema.
